# OSI Model Analysis Using Wireshark

## 1. Objective

Capture network traffic generated by my Kali Linux computer and inspect a packet to understand how real network protocols relate to the OSI model.

## 2. Lab Environment

- Operating system: Kali Linux
- System: Physical computer (bare metal)
- Network connection: Wi-Fi
- Capture interface: wlan0
- Packet analyzer: Wireshark

## 3. Procedure

1. Checked the active network interface using `ip -br addr`.
2. Started a Wireshark capture on `wlan0`.
3. Generated traffic using `ping -c 4 1.1.1.1`.
4. Applied the display filter `icmp`.
5. Selected Frame 83, an ICMP Echo Request.
6. Expanded the Ethernet II, IPv4, and ICMP sections.
7. Recorded the observed header fields.

## 5. OSI Layer Mapping

### Layer 1 — Physical

The physical layer carries bits over the wireless medium using radio signals. Wireshark does not display these signals as a conventional packet header.

### Layer 2 — Data Link

The Ethernet II section exposes the source MAC address, destination MAC address, and EtherType. These fields describe link-layer delivery.

### Layer 3 — Network

The IPv4 header contains the source address `192.168.0.5`, destination address `1.1.1.1`, TTL, and protocol identifier.

The ICMP section identifies the message as an Echo Request used by the ping diagnostic utility.

### Layer 4 — Transport

This packet does not contain a TCP or UDP header. ICMP is associated with the network layer and does not use TCP or UDP ports.

### Layers 5–7 — Session, Presentation, and Application

This ICMP packet does not establish separate headers for these layers. Their functions can be studied using other protocols and examples.
